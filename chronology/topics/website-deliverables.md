# 我让 AI 帮我做个网站，拿回来的是图、代码，还是一个网址？

一位网友晒出几张网页改版图。有人选中了最喜欢的那张，也有人想知道到哪里能点开它。从这条追问出发，看三个不同的现场：挑界面、审代码、把应用交给同事。它们各自在哪一步交到了人手里？

## Nano Banana：一张图可以接着改

**实际拿到什么**　几张网页改版效果图。把它们摆在一起，就能讨论哪种布局更好看。

**人接下来做什么**　选出想要的设计。若希望访客能点击菜单、提交表单，还要有人把画面实现成网页。

2025 年 8 月 27 日的 Reddit 原帖给出了改版提示词。评论里有人追问画面能否当网站使用，得到的回答是图片。 [Reddit原帖：Nano Banana is a great web designer](https://www.reddit.com/r/Bard/comments/1n1o4eo/nano_banana_is_a_great_web_designer/)

## 把代码任务交给 Copilot，等它交回待审修改

**实际拿到什么**　仓库里多了一份草稿拉取请求（PR）。开发者能逐行查看代理为这个任务改了哪些文件。

**人接下来做什么**　写清问题单，检查代码差异，必要时留言让代理再改。是否合并，由审阅者决定。

GitHub 在 2025 年 5 月的预览说明中展示了从分配问题单到交回草稿 PR 的流程；这个例子说明代码怎样交接。 [GitHub Copilot: Meet the new coding agent](https://github.blog/news-insights/product-news/github-copilot-meet-the-new-coding-agent/)

## Cursor：写出的应用，可以继续上线给别人用

**实际拿到什么**　发布后得到一个可以分享的应用网址。按 Cursor 公告的例子，团队可以用它做活动报名；需要保存记录时，代理能准备数据库和登录入口。

**人接下来做什么**　选择域名，处理检查发现的问题，明确确认发布，再把链接发给使用者。

Cursor 在 2026 年 11 月 5 日的更新说明中列出了托管条件和发布步骤。报名工具是公告举例。 [Cursor：Build Live Apps in Cursor](https://cursor.com/changelog/build-live-apps)

如果明天就要请同事报名，看到效果图时可以挑设计，收到草稿 PR 时可以审改动，拿到网址后才轮到同事试填。这三个现场来自不同任务，比较的是交接时手里有什么。

交付物能点开，能回答“做到了哪一步”。至于“我有没有少花时间”，还得看工时。METR 让开发者在自己熟悉的项目里实际计时，结果和他们的体感相反。 [开发者觉得更快，实验却测到了更慢](../2025.md#event-metr-experienced-developers-rct)
