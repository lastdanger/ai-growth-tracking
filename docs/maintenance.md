# 内容维护

先检索原始来源、判断入选意义，再更新 `data/map.json`。来源直接登记，不强制研究简报或章节卡；需保留比较判断时放 `research/audits/`，未核线索留内部研究。

## 校验与生成

```powershell
node scripts/check.mjs
node --test scripts/check.test.mjs
node scripts/build.mjs
```

check 检查唯一 ID、时间、来源、年度锚点、关系与伏笔证据；build 生成离线网页 `dist/index.html` 和 `chronology/` 年表。生成文件不手改。

交互修改后检查年度选择、主次展开、详情、相关跳转、返回与窄屏。纯内容修改检查数据与对应页面，不机械写镜像实现的测试。

当前 schema_version 为 3，保留 v2 的年度代表入口、显式 display_groups、reading_routes、事件 change 和材料 temporal_context，新增 series。系列通过 event_id 引用共用事件，每项须说明关联理由并区分 key/supporting；条目按事件日期及 ID 排序，非末关键站必须有转场。系列 as_of 不得超出内容包日期，覆盖说明须明确截止和缺口。关键站不自动成为年度 main。

分支未指定展示父节点时，自动进入平级的月份同期组；不能恢复按关系数组首项或邻近日期挂接。修改推荐路线时同步检查转场、跨年下一站与退出路线；路线引用现有事件，不复制正文。系列交互另查跨年、补充节点关闭后焦点、系列外事件返回、刷新与历史。更新计数和本地/线上版本时同步 README 与总账首页。

`updated_at` 是整包内容更新日；各年 `as_of` 保留该年的核验截止日。只补历史年份时，不把进行中年份的截止日一起改成今天。

当前任务与选材、年度关键词、事实更正的简短修订收据进入 本地维护记录。旧核验日期保留在内部来源档案；旧 CH/EX 等仅为历史标识，不代表仍有章节要写。

系列关键站必须提供事件 change，页面据此展示“为什么重要”；转场要接住前一站的具体问题，并在下一站正文中得到回应。每系列通常保留5—8个关键站，不将每次最新发布自动升级。阅读次序已由series表达，不再为相邻站机械复制context关系；事实联系、跨系列采用与值得展开的分支才进入relations。

网页默认链接或必要短引，图片、音视频再发布另核权利。本地构建不等于发布授权，不自动采集或定时更新。
