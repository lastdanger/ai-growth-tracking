# 内容维护

先检索原始来源、判断入选意义，再更新 `data/map.json`。来源直接登记，不强制研究简报或章节卡；需保留比较判断时放 `research/audits/`，未核线索留内部研究。

## 校验与生成

```powershell
node scripts/check.mjs
node --test scripts/check.test.mjs
node scripts/build.mjs
```

check 检查唯一 ID、时间、来源、年度锚点、关系与伏笔证据；build 生成离线网页 `dist/index.html` 和 `chronology/` 年表。生成文件不手改。

交互修改后检查年度选择、主次展开、详情、相关跳转、返回与窄屏。纯内容修改检查数据与对应页面，不机械写镜像实现的测试。

当前 schema_version 为 3，保留 v2 的年度代表入口、显式 display_groups、reading_routes、事件 change 和材料 temporal_context，新增 series。系列通过 event_id 引用共用事件，每项须说明关联理由并区分 key/supporting；条目按事件日期及 ID 排序，非末关键站必须有转场。系列 as_of 不得超出内容包日期，覆盖说明须明确截止和缺口。关键站不自动成为年度 main。

分支未指定展示父节点时，自动进入平级的月份同期组；不能恢复按关系数组首项或邻近日期挂接。修改推荐路线时同步检查转场、跨年下一站与退出路线；路线引用现有事件，不复制正文。系列交互另查跨年、补充节点关闭后焦点、系列外事件返回、刷新与历史。README 提供读者入口，内容范围可由地图数据和公开版本记录核对。

`updated_at` 是整包内容更新日；各年 `as_of` 保留该年的核验截止日。只补历史年份时，不把进行中年份的截止日一起改成今天。

系列入口可用 `series_timeline` 选取一段连续月份。每行对应一个模型家族，用已有事件 ID 与短标签标出确切日期，也可以选入尚无独立系列的家族。观察日决定可见节点和回看日期。试读节点沿用原档案的 `then` 与 `later`，分别写明当时可知的事实、后来模型自身的变化及对手带来的新选择。网页和系列目录文字版共用这份选材。

节点的 `kind` 取自 `series_timeline.legend.kinds`，按该日发生的主要变化标记。类型的底色、符号和名称都由这份图例给出。日期旁的“已有回看”标签随观察日出现。构建会把同款标签写入 `chronology/series/legend-*.svg`，供文字版和 README 离线显示。调整试读节点时，同步 README 的示例。

首页的 `recent_update` 保存本期选材截止、导语和事件 ID。换期时替换这组引用，最多选三件在首页直接展示，其余仍可展开。专题放在可选的 `topics` 中。首篇各用一项已有事件和该事件的一条出处解释交付物、人还要做什么、材料能证明什么，再给出一则有理由的延伸阅读。网页与年表由同一次构建生成。

比较价格时写清比较对象、任务、计量单位和观察日期。比较赛况时交代规则与作品出处，社区投票、厂商演示和独立测试各按自身范围引用。有可对照的材料再组织专题。

当前任务与选材、年度关键词、事实更正的简短修订收据进入 本地维护记录。旧核验日期保留在内部来源档案；旧 CH/EX 等仅为历史标识，不代表仍有章节要写。

系列关键站必须提供事件 change，页面据此展示“为什么重要”；转场要接住前一站的具体问题，并在下一站正文中得到回应。每系列通常保留5—8个关键站，不将每次最新发布自动升级。阅读次序已由series表达，不再为相邻站机械复制context关系；事实联系、跨系列采用与值得展开的分支才进入relations。

系列outro总结阶段变化，exit只选一个有具体理由的非关键站出口，事件日期不晚于系列截止。supporting条目用return_to指定本系列关键站及衔接理由；不使用通用“继续下一次变化”代替解释。修改后检查末站、出口、补充分支返回和历史恢复。个人使用自述须写明型号、环境及可证明的范围；持续修订的评测不能冒充首版快照，后续材料不得混入首发成绩。

网页默认链接或必要短引，图片、音视频再发布另核权利。本地构建不等于发布授权，不自动采集或定时更新。
